#+title: Dockerized Claude Code

Run Claude Code in a container (also driven from Emacs) to provide
file system isolation and protect your secrets. =git= uses tokens from
each project's =.env=. Claude uses OAuth tokens retrieved via macOS'
=keychain= (fallback: read from an unencrypted file with the implied
security risks), or talks to an LLM gateway (LiteLLM) when one is
configured — see [[#llm-gateway-litellm][LLM gateway (LiteLLM)]].

* Files

#+begin_example
bin/
  claude-docker.sh        Wrapper script -> ~/.local/bin/claude-docker (+ codex-docker symlink)
container/
  Dockerfile              Claude Code + OpenAI Codex based on node 22
  entrypoint.sh           git tokens -> exec claude
  git-credential-token    Credential helper (reads tokens from env)
skills/
  <name>/SKILL.md         Skills baked into every container (submodule or dropped-in)
elisp/
  claude-code-ide-ext.el  Emacs configuration
.env.example              Template .env for projects
#+end_example

* Setup

#+begin_src sh
make install && make build
#+end_src

=install= copies container files to =~/.config/claude-devcontainer/= and the
wrapper to =~/.local/bin/claude-docker=. =build= builds the Docker image.

/Alternatively, do the following manually:/
#+begin_src bash
# 1. Copy container files
mkdir -p ~/.config/claude-devcontainer
cp container/Dockerfile container/entrypoint.sh container/git-credential-token \
   ~/.config/claude-devcontainer/
chmod +x ~/.config/claude-devcontainer/entrypoint.sh \
         ~/.config/claude-devcontainer/git-credential-token

# 2. Build image
docker build -t claude-devcontainer ~/.config/claude-devcontainer/

# 3. Install wrapper (codex-docker is the same script under a second name)
cp bin/claude-docker.sh ~/.local/bin/claude-docker
chmod +x ~/.local/bin/claude-docker
ln -sf claude-docker ~/.local/bin/codex-docker

# 4. Test it
make test

# 5. Add to your Emacs init (see Emacs section below)

# 6. Add token to your project
cd ~/your-project
cp /path/to/repo/.env.example .env   # paste your token
echo '.env' >> .gitignore
#+end_src

* Per-project .env

See [[file:.env.example][=./.env.example=]]

# GitHub: https://github.com/settings/tokens (fine-grained, per-repo)
GITHUB_TOKEN=

* OAuth

The OAuth token is read from Keychain via:
#+begin_src sh
security find-generic-password -s 'Claude Code-credentials' -w 2>/dev/null
#+end_src

Fallback: =~/.config/claude-devcontainer/env=. Since credentials are stored in
clear in that file, the Keychain approach is strongly preferred.

*Less secure variant:* If you cannot use Keychain:
#+begin_src bash
claude setup-token
echo "CLAUDE_CODE_OAUTH_TOKEN=sk-ant-...." > ~/.config/claude-devcontainer/env
chmod 600 ~/.config/claude-devcontainer/env
#+end_src

With =--env= (next section) the OAuth token is not read at all.

* LLM gateway (LiteLLM)
:PROPERTIES:
:CUSTOM_ID: llm-gateway-litellm
:END:

Use a [[https://docs.litellm.ai/][LiteLLM]] proxy instead of your Anthropic account:

#+begin_src sh
claude-docker --env my-gateway/gateway.sh
codex-docker  --env my-gateway/gateway.sh
#+end_src

The file exports the gateway URL, your key and, if the gateway names models
differently from Anthropic, the model IDs:

#+begin_src bash
_dir="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
[ -f "$_dir/key.env" ] && . "$_dir/key.env"          # LITELLM_API_KEY=sk-…
export LITELLM_API_KEY

export ANTHROPIC_BASE_URL="https://llm-gateway.example.invalid"
export ANTHROPIC_AUTH_TOKEN="$LITELLM_API_KEY"       # or ANTHROPIC_API_KEY for x-api-key

export ANTHROPIC_DEFAULT_OPUS_MODEL="<gateway id for opus>"
export ANTHROPIC_DEFAULT_SONNET_MODEL="<gateway id for sonnet>"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="<gateway id for haiku>"
export ANTHROPIC_DEFAULT_FABLE_MODEL="<gateway id for fable>"
#+end_src

Keep the key in =key.env= next to it (=chmod 600=, git-ignored). The whole
directory is visible inside the container, so keep nothing else private in it
and don't use it as a workspace.

- Without =--env= nothing changes.
- With =--env= your Anthropic login is not used; git tokens work as usual.
- Use a named instance (=-i gw=) and run =/logout= in it once, otherwise
  Claude Code warns about two credentials at every start.
- =ANTHROPIC_*= and =CLAUDE_CODE_*= settings from your shell are passed on;
  the file wins where both set the same variable.
- Emacs: add =--env …= to =claude-code-ide-cli-extra-flags=.

** Codex

=codex-docker= runs [[https://github.com/openai/codex][OpenAI Codex]] with the same flags. For a gateway, add two
files to the directory:

#+begin_example
my-gateway/
  gateway.sh          as above
  key.env             LITELLM_API_KEY=…
  codex-setup.sh      runs at every container start
  codex/config.toml   Codex provider config
#+end_example

#+begin_src bash
# codex-setup.sh — runs from my-gateway/, must be safe to repeat
[ -f "$CODEX_HOME/config.toml" ] || cp codex/config.toml "$CODEX_HOME/config.toml"
#+end_src

#+begin_src toml
# codex/config.toml
model = "<gateway model id>"
model_provider = "gateway"
web_search = "disabled"          # not supported through LiteLLM

[model_providers.gateway]
name = "LiteLLM"
base_url = "https://llm-gateway.example.invalid/v1"
env_key = "LITELLM_API_KEY"
wire_api = "responses"
#+end_src

=codex-setup.sh= can also generate a model catalog (=model_catalog_json=) so
=/model= offers reasoning efforts for the gateway's models.

Codex keeps its state in a Docker volume per instance, separate from your
host =~/.codex=. Reset it with =docker volume rm claude-devcontainer-codex=.
Without =--env=, use =codex login= inside the container or set =OPENAI_API_KEY=.

* Git remote rewriting

When a git token is present in the project =.env=, SSH remote URLs are
automatically rewritten to HTTPS so Claude Code can push from inside the
container (which has no SSH client).

When =.env= is absent or contains no git token, rewriting is skipped
automatically. You can also control this explicitly:

#+begin_src conf
CLAUDE_NO_GIT_REWRITE=1   # always skip rewriting (even if a token is set)
CLAUDE_NO_GIT_REWRITE=0   # always rewrite (even without a token in .env)
#+end_src

Set this in your shell environment or in the project =.env=.

* Named instances

Run multiple Claude agents on the same codebase without conflicts.
Each named instance gets its own isolated state directory under
=~/.config/claude-devcontainer/instances/<name>/=.

#+begin_src sh
# Launch two agents in parallel
claude-docker -i stan
claude-docker -i kyle
#+end_src

Instance state is stored in:
#+begin_example
~/.config/claude-devcontainer/instances/
  stan/
    .seeded          # Sentinel: seed dir was populated from host
    claude/          # Seed — credentials copied once from ~/.claude (read-only in container)
    claude.json      # Claude account config (~/.claude.json), writable
    state/           # Persistent session state (conversation history, memory, settings)
  kyle/
    ...
#+end_example

On first launch, credentials are copied from =~/.claude/= into =claude/=
(the seed). Inside the container the seed is mounted read-only; the
=state/= directory is mounted read-write and seeded from =claude/= on
first use. After that every session reads and writes =state/= directly —
conversation history, project memory, and settings all persist across
runs.

This split keeps the original credentials frozen in =claude/= (they can
never be modified from inside the container) while =state/= accumulates
freely.

Stale instances (unused for 7 days) are pruned automatically. To
manually prune a specific instance:
#+begin_src sh
claude-docker -i kyle --prune
#+end_src

To re-seed an instance (e.g. after re-authenticating on the host):
#+begin_src sh
# 1. Re-copy fresh credentials from ~/.claude into the seed dir
rm ~/.config/claude-devcontainer/instances/stan/.seeded
# 2. Clear accumulated state so the container re-initialises from the new seed
rm -rf ~/.config/claude-devcontainer/instances/stan/state/
#+end_src

To list all instances with their associated project and status:
#+begin_src sh
claude-docker --list
#+end_src

#+begin_example
INSTANCE             STATUS     LAST USED            PROJECT
--------             ------     ---------            -------
stan                 running    2026-03-23 14:05     /home/user/project-a
kyle                 stopped    2026-03-21 09:30     /home/user/project-b
#+end_example

Without =--instance=, the default behaviour is unchanged: =~/.claude= is
shared and the concurrent-instance warning remains active.

* Skills

Skill directories under =skills/= are baked into the image and injected into
=~/.claude/skills/= inside every container on startup, so each container ships
with them available to Claude Code. The bundled default is
[[https://github.com/blader/humanizer][=blader/humanizer=]].

Add a skill either as a git submodule (tracks upstream) or by dropping a
folder in — both require a =SKILL.md= at the top of the skill directory:

#+begin_src sh
# As a submodule (SKILL.md must be at the repo root, as in blader/humanizer)
git submodule add https://github.com/<owner>/<repo> skills/<name>

# Or drag-and-drop a vendored skill
mkdir -p skills/<name> && cp /path/to/SKILL.md skills/<name>/

make install    # inits submodules, ships skills/ into the build context
make build      # rebuild so the new skill is baked in
#+end_src

Injection is *non-destructive*: a baked skill is copied only when
=~/.claude/skills/<name>= doesn't already exist, so your own edits (and host
skills of the same name in a shared =~/.claude=) always win. To refresh an
injected skill after rebuilding, delete =~/.claude/skills/<name>= (in the
relevant instance state) and restart. Set =CLAUDE_SKIP_SKILLS=1= to skip
injection for a run.

Cloning this repo? Pull the skill submodules with:
#+begin_src sh
git submodule update --init --recursive
#+end_src

See [[file:skills/README.md][=skills/README.md=]] for details. Skills are baked
by =Dockerfile.full= (the image =make build= produces).

* Network

No firewall — full network access. Protection is *filesystem isolation*: the
container only sees the current project directory.

* Emacs

=elisp/claude-code-ide-ext.el= extends
[[https://github.com/manzaltu/claude-code-ide.el][claude-code-ide]] with Docker wrapper support, named instances,
and an optional native (non-dockerized) mode.

** Installation

With =use-package= + =straight.el= (recommended):

#+begin_src emacs-lisp
(use-package claude-code-ide-ext
  :straight (:type git :host github :repo "jgru/claude-code-container"
             :files ("elisp/claude-code-ide-ext.el")))
#+end_src

Or load from a local checkout:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/claude-code-container/elisp")
(require 'claude-code-ide-ext)
#+end_src

** Commands

| Key / command                              | Description                                   |
|--------------------------------------------+-----------------------------------------------|
| =C-c C-'=                                 | Open Claude Code menu                         |
| =M-x claude-code-ide-ext-start=           | Start Claude with a named instance (completing)|
| =M-x claude-code-ide-ext-set-instance=    | Set instance name for the current buffer      |
| =M-x claude-code-ide-ext-list-instances=  | List all instances with status                |
| =M-x claude-code-ide-ext-prune-instance=  | Prune a stopped instance                      |
| =M-x claude-code-ide-ext-toggle-docker=   | Toggle between Docker and native CLI          |
| =M-x claude-code-ide-ext-init-env=        | Scaffold =.env= and add it to =.gitignore=   |

** Per-project instance name

Set a default instance per project via =.dir-locals.el=:

#+begin_src emacs-lisp
((nil . ((claude-code-ide-ext-instance . "stan"))))
#+end_src

** Customization

| Variable                              | Default                        | Description                      |
|---------------------------------------+--------------------------------+----------------------------------|
| =claude-code-ide-ext-docker-cli=      | =~/.local/bin/claude-docker=   | Path to the Docker wrapper       |
| =claude-code-ide-ext-bare-cli=        | =claude=                       | Path to the native CLI           |
| =claude-code-ide-ext-use-docker=      | =t=                            | Use Docker wrapper when non-nil  |
| =claude-code-ide-ext-instances-dir=   | =~/.config/claude-devcontainer/instances/= | Instance state directory |
